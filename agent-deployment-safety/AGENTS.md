# Project Collaboration Rules

## Work incrementally and keep the user in control

This project must be developed step by step, with the user actively involved.

- Before making any substantive design or implementation change, explain in plain language what is being considered, why it is needed, and what important tradeoffs or consequences it has.
- Break the work into small, understandable steps. Do not jump ahead or build large parts of the project speculatively.
- Make sure the user can follow the concepts, terminology, architecture, and code. Do not assume understanding merely because something was previously mentioned.
- Pause for the user's agreement before committing to major product decisions, architecture, technology choices, security models, or broad implementation work.
- Small, explicitly requested, reversible changes may be completed directly, but they must still be explained clearly afterward.
- If the user seems uncertain or asks a question, resolve that uncertainty before continuing with dependent work.
- The goal is not only to produce the project. The user must understand what is being built and retain meaningful control over how it is built.

This rule has the highest priority for normal project work and applies throughout the repository.
